# Rust、Tauri 与本地服务规则

- 沿用功能模块组织：`commands.rs` 暴露 IPC，`http.rs` 适配 HTTP，`db.rs` 负责持久化；入口不堆叠业务逻辑。
- 保持 HTTP、IPC、CLI 的业务语义一致，复用合适的共享逻辑；返回包装和错误格式分别遵循各入口已有契约。
- 新 command 检查 `lib.rs` 注册；插件或原生能力变化检查 capability、配置和平台条件编译。
- 可恢复失败使用 `Result` 传播并在边界转换；新增用户输入、I/O、数据库路径不使用无说明的 `unwrap` / `expect`。
- SQL 使用参数绑定；涉及多步写入明确事务边界，保留 WAL 和外键，数据库结构变化验证已有数据升级。
- 任务分支为软删除；域名为物理删除并级联 Cookie / localStorage，修改这些语义需要明确的需求依据。
- GUI、HTTP、CLI 需定位到同一应用数据目录，不能在工作目录另造数据库。
- 本地 HTTP 当前仅监听 `127.0.0.1:8765`。网络绑定、CORS、请求体限制变化需明确说明影响，不顺带扩大服务暴露面。
- 保留 `/push` 已有兼容解析；Serde 字段、HTTP 查询和 IPC 参数分别核实。
- 避免长时间持锁、持锁跨 `await` 或阻塞运行时；按实际调用路径选择任务调度方式，不为简单同步逻辑引入复杂框架。
- CLI 的业务 JSON 输出与诊断信息分离，注意 Windows GUI / console 子系统差异。
- 日志不记录真实 Cookie、token 或完整 localStorage；`unsafe` 需说明安全前提。
- 仅格式化涉及的代码，不为修复格式检查重排整个项目；验证按公共测试规则执行。
