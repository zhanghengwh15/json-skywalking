# 验证规则

按变更影响选验证方式，记录命令、结果与限制，不为可逆低影响修改编写镜像实现的测试。

| 变化 | 验证 |
| --- | --- |
| Vue / TypeScript | `npm run build`；受影响交互在适当运行环境手动验证 |
| Rust | `cargo check --manifest-path src-tauri/Cargo.toml`；业务逻辑按需执行 `cargo test --manifest-path src-tauri/Cargo.toml` |
| IPC / HTTP / CLI 契约 | 核对参数、序列化、空值和错误；对适用入口做行为验证 |
| SQLite | 使用临时数据库验证初始化、已有数据升级、事务、软删或级联行为 |
| 桌面能力 | 在 `npm run tauri dev` 环境验证托盘、快捷键、剪贴板和生命周期 |
| 安装与发布 | 在目标平台验证产物、PATH 和二进制输出，标记未覆盖平台 |
| 仅文档 / 规则 / 技能 | 校验引用、目录、YAML 和技能元数据，无需完整构建应用 |

- 当前 npm 未配置 `test`、`lint` 脚本，不编造这些检查或覆盖率门槛。
- 浏览器预览不能证明 IPC 或原生桌面能力通过。构建通过不能替代业务验收。
- 验证数据使用临时文件和虚构 Cookie / token；不清空用户真实应用数据或借用真实登录态。
- 编译、联网或平台环境阻塞时，记录失败原因及未覆盖部分，不写“已通过”。
- 测试文档按 [docs-prd.md](docs-prd.md) 归档，预期结果与执行结果分开。
