# 增量修改约定

- 理解需求和相邻代码后修改，优先沿用当前模块组织、错误处理和样式。
- 保持改动聚焦，不为了统一风格改全文件，不夹带重构或依赖升级。
- 命名体现对象、动作和必要单位，避免同一概念在 IPC、HTTP、CLI 与文档中改名。
- 业务判断保持明确；非法输入与外部失败应反馈，不能用空值或成功状态吞掉错误。
- 公共契约使用明确类型；复用当前实现，出现真实重复或复杂度时再提取抽象。
- 不手改 `dist/`、`target/`、`node_modules/` 或 Tauri 生成文件；锁文件只随相关依赖变化更新。
- 保留已有用户改动，不删除未跟踪文件，不修改参考项目来完成当前项目任务。
- 涉及 API、持久化、权限或平台差异时，同步维护相关文档；读取 [docs-prd.md](docs-prd.md)。
