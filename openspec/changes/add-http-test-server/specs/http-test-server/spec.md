## ADDED Requirements

### Requirement: 可配置的本地 HTTP 测试服务
系统 SHALL 允许在桌面页面配置端口及多个精确 URL、方法、200–599 状态码、自定义响应体和 Content-Type，手动启动或停止，仅监听 127.0.0.1；非法配置、重复或冲突路由和端口占用 MUST 明确报错。默认响应 MUST 保持 code=0、message=ok、data=null 的 JSON 示例，每个接口 MUST 允许独立完整替换为最多 64 KiB 的任意 UTF-8 文本或空内容，原样返回且不强制 JSON 格式。

#### Scenario: 任意入参返回固定数据
- **WHEN** 配置 POST /test 并使用任意 JSON、表单、文本、空请求体或查询参数调用
- **THEN** 服务返回配置的状态码、Content-Type 和响应原文；查询参数不改变 URL 匹配

#### Scenario: 自定义正文与旧配置兼容
- **WHEN** 用户停止服务后将响应改为数组 JSON、文本、HTML、XML 或空内容，并重新启动
- **THEN** 对应接口按原文返回，其他接口保持各自响应；成功启动保存配置，应用重启恢复配置但不自动监听，旧配置缺少 Content-Type 时使用 application/json; charset=utf-8

#### Scenario: 协议与响应类型边界
- **WHEN** 用户配置超过 64 KiB 的正文，或空白、超过 256 字符、含换行或非可打印 ASCII 字符的 Content-Type
- **THEN** 页面与后端均拒绝配置并反馈原因；合法配置下 HEAD、204、205、304 仍不返回正文，系统 404 和正文读取错误保留原有错误 JSON

#### Scenario: 生命周期与占用
- **WHEN** 端口被占用或用户重复启动
- **THEN** 服务返回错误且不会覆盖运行配置；停止成功后释放端口，应用重启不自动监听

#### Scenario: 未匹配与边界
- **WHEN** 调用未配置的路径或方法、发送浏览器预检或超过 1 MiB 请求体
- **THEN** 分别返回 404、204 或 413，正常请求支持浏览器跨域调用

### Requirement: 请求日志页面
系统 SHALL 在独立日志页面记录请求时间、端口、方法、URL、来源地址、脱敏请求头、请求体、状态码、耗时及响应体，提供筛选、详情、刷新和清空。日志 MUST 有界并标注截断，只保留当前进程最近 200 条。

#### Scenario: 请求可追踪
- **WHEN** 请求成功或因路径未匹配失败
- **THEN** 日志页面刷新后可查看相应请求与返回，并可按 URL 或方法筛选

#### Scenario: 切换页面与清空
- **WHEN** 用户离开服务页面再打开日志页面或清空日志
- **THEN** 已接收日志仍可查看，清空后列表与详情同步为空

### Requirement: 生成调用文档
系统 SHALL 根据当前有效配置生成 Markdown 说明，包含监听地址、端口、各接口方法和路径、任意入参约定、固定响应和可执行 curl 示例，支持预览和保存 MD 文件。

#### Scenario: 导出当前配置
- **WHEN** 用户修改配置并导出文档
- **THEN** 导出内容与配置一致，显示文件保存位置，并说明需要启动服务及日志保留范围

### Requirement: 快速生成 cURL
系统 SHALL 为每个接口提供「生成 cURL」按钮，展示可选取的只读命令并支持复制；SHALL 支持页面内 ⌘ / Ctrl + Alt + C，为最近聚焦或点击的接口生成命令，未选择时使用第一个接口。命令 MUST 按生成时端口、路径、方法构造，不自动执行请求；ANY 使用 POST 示例，HEAD 使用 --head；页面与导出文档 MUST 复用生成规则。

#### Scenario: 生成和复制指定接口
- **WHEN** 用户点击第二个接口的生成按钮，或聚焦第二个接口后使用快捷键
- **THEN** 展示第二个接口的 cURL；点击复制后反馈成功，剪贴板不可用时提示从命令框手动复制；非法配置显示错误
