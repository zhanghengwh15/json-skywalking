# cURL 格式化需求

## 背景与目标

浏览器或工具导出的 cURL 常含 `--data-raw`、`--json`、Bash 专用引号以及 Markdown 链接，复制到内部旧版 Linux 后可能无法运行。用户希望新增独立菜单，将请求转为常用旧参数格式，便于反复使用。

用户已确认目标版本未知，按 cURL 7.29 兼容目标实施。原始附件为一条包含 JSON、SQL、业务模板占位符和认证请求头的命令；仓库文档与测试仅使用虚构数据。

## 范围与功能

| 编号 | 功能与规则 |
| --- | --- |
| FR-01 | 侧边栏增加“cURL格式化”，独立页面支持粘贴、示例、清空与快捷键转换。 |
| FR-02 | 新版正文参数转换为 `--data-binary`（默认）或 `-d`；保留显式方法、URL、请求头、Cookie 和已支持选项。 |
| FR-03 | 解析普通单 / 双引号、POSIX 单引号拼接、浏览器导出的 Bash ANSI-C 引号、单行 / 多行及 CRLF 续行；恢复 Markdown URL，展示修正项。 |
| FR-04 | 不重新序列化 JSON；保留 SQL、Unicode、业务模板与大整数原文。可选择补齐 JSON Content-Type；转换 `--json` 时保留其默认 JSON 请求头语义，已有头优先。 |
| FR-05 | 支持单行 / 多行输出和一键复制；输入修改后清空旧结果，选项变化后重新转换。 |
| FR-06 | 引号未闭合、多 URL、未知 / 不兼容参数、无法无损转换的组合给出明确错误；文件正文、无效 JSON 显示说明。 |
| FR-07 | 所有处理在当前页面内完成，不执行请求、不运行输入命令、不保存或记录认证数据。 |

本期包含菜单、页面、转换器、文档规则和验证；不增加历史记录、接口执行、后端服务、数据库或目标 Linux 的安装能力。

## 异常与兼容边界

- 仅接收一条 cURL、一个 HTTP / HTTPS URL；不运行或解释 Shell 变量和命令替换。
- 以 `@` 开头的 `--data-raw` 不能盲目转成文件读取，明确报错；原有文件正文保留读取语义，提示运行环境需提供文件。
- 多个内联 `--json` 按原语义直接拼接；与其他正文混用或多个文件不能离线合并时拒绝转换。
- 支持的 ANSI-C 转义可转为普通 Shell 参数；NUL、无法无损表达的非 ASCII 原始字节等报错。
- 无效 JSON 保留正文并提示，不擅自修正业务数据。普通单引号 JSON 中明显的 `\'` 粘贴问题单独修复并报告。
- 页面“7.29 兼容目标”描述参数兼容目标，不代表已在用户服务器验证其证书、TLS、网络和可选构建功能。

## 验收标准

| 编号 | 可观察结果 |
| --- | --- |
| AC-01 | 点击新菜单可进入 `/curl-formatter`；示例、空态、清空及快捷键可用。 |
| AC-02 | 示例及用户附件离线转换后不含作为选项的 `--data-raw` / `--json`，可切换两种正文参数。 |
| AC-03 | Shell 参数捕获验证 SQL 引号、JSON 转义、Unicode、模板占位符、大整数及多行正文保持一致。 |
| AC-04 | `--json` 默认请求头补齐，已设置或明确抑制的同名头保留；普通 JSON 的补头开关生效。 |
| AC-05 | 不兼容参数和损坏输入显示错误、无旧结果可复制；文件依赖与 JSON 问题可见。 |
| AC-06 | 单行 / 多行切换及复制可用，编辑输入立即使旧输出失效；不触发目标 API 请求。 |
| AC-07 | `npm run build` 与 `npm run test:curl` 通过，记录页面操作和实际平台验证范围。 |
