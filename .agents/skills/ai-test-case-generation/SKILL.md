# Dev Tools 测试用例

先读 `AGENTS.md`、`.codex/rules/common/docs-prd.md` 和 `.codex/rules/common/testing.md`。

## 输入与输出

- 优先使用用户指定的 PRD 和当前需求目录；同名多候选且无法判定时再澄清。
- 读取相关 LLD / FLD、OpenSpec 和契约，只对当前范围派生场景。
- 输出到 `docs/产品文档/{需求}/testcase/testcase-{场景}-{YYYY-MM-DD}.md`，沿用既有文件和稳定用例编号。
- 若缺 PRD，用户输入可作为需求来源，明确来源和覆盖限制，不为了写测试擅自编一套产品需求。

## 用例格式

每条包含用例编号、关联 `FR-*` / `AC-*`、优先级、入口与平台、前置条件、输入 / 步骤、可观察预期。执行结果单独记录，生成时默认“未执行”。给出需求到用例的覆盖表及缺口。

按影响选择场景：

- 解析工具：空值、无效格式、Unicode、大输入、格式化与历史恢复。
- IPC / HTTP / CLI：字段、可空、错误、兼容格式、重复操作与输出行为。
- Cookie / 域名：未传与空数组区别、镜像写入、事务、域匹配与级联删除。
- 任务分支：筛选、CRUD、软删除及已删除数据不可见。
- SQLite：临时库初始化、已有数据升级、外键与回退兼容。
- 桌面能力：快捷键、剪贴板、托盘、关闭 / 退出；按实际目标平台验证。
- 本地服务：端口占用、非法请求、体积限制等受影响行为。

测试数据使用临时数据库和虚构凭据。未实际执行时不填“通过”；执行失败或平台不可用如实记录。更新 MOC 和元数据，不自动改变 PRD 或实现状态。
