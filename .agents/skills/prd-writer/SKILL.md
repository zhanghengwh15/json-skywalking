# Dev Tools PRD

先读根目录 `AGENTS.md` 和 `.codex/rules/common/docs-prd.md`，按规则定位当前需求目录。

## 工作方式

1. 从用户输入和原始资料提取使用者、问题、目标与本期范围。已明确的信息直接沿用，缺失但不阻塞的信息标注待确认。
2. 需要描述已有行为时，核实相关 Vue 页面、Rust command / HTTP / CLI 和模型。业务目标来自用户需求，代码用于说明现状与可实施性。
3. 区分已实现行为、拟新增功能和假设；新功能可提出契约需求，但不得描述成现有接口。
4. 写入 `docs/产品文档/{需求}/prd/PRD-{需求}.md`，增量维护同目录已有 PRD。
5. 更新需求 `MOC.md` 和 `docs/README.md` 的真实链接；不提前创建未生成产物。

## 内容判断

- 至少包含背景、目标、范围、功能规则和验收标准；规模较小时合并章节。
- 用 `FR-01` 标识功能，用 `AC-01` 标识验收，保留已有编号，便于设计和测试追踪。
- 场景按实际需求覆盖桌面 UI、浏览器扩展、本地 HTTP 调用方或 CLI 脚本，不强行加入所有入口。
- 明确空输入、非法格式、重复操作、时间单位、失败反馈和适用的平台差异。
- Cookie / 域名需求明确镜像更新、未提供字段、级联删除等业务语义；任务分支需求明确软删除语义。
- 技术拆分放入 LLD / FLD，接口细节引用现有对接文档，避免复制出另一份契约。

交付给出文档路径、关键待确认项与覆盖范围。文档状态遵循规则，不能把文档完成写成实现或验收完成。
